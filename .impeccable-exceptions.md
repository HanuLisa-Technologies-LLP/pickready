# Impeccable exceptions

Every finding `npx impeccable detect` reports that this repository has decided
NOT to fix, with the reason. `frontend/scripts/impeccable-gate.mjs` reads this
file's table in CI and fails on anything that is not listed here, so an
exception is a reviewed line in a diff rather than a warning somebody scrolled
past.

**The rule for adding a row.** An exception is justified only when the flagged
pattern is carrying INFORMATION that the alternative would lose. "It looks
better" is not a reason; "removing it would make two different things look the
same" is. If the reason cannot be written in one sentence naming what would be
lost, the finding should be fixed instead.

---

| Antipattern | File | Reason |
|---|---|---|
| `side-tab` | `frontend/components/functional-skills-report.tsx` | The left rule marks the **Validation** section: the candidate's own unrated words, reproduced exactly as submitted. That boundary is the point of the section. A reader has to be able to tell what the candidate SAID from what the platform CONCLUDED, and removing the rule would make the two look identical on a page where confusing them changes a hiring decision. |
| `side-tab` | `frontend/components/posting-window.tsx` | The rule's COLOUR carries the posting state — live, in its five-day grace tail, or closed. The rule IS the information rather than a decoration beside it, and the states are also labelled in words, so the colour is not carrying it alone. |
| `side-tab` | `frontend/components/candidate-dashboard/candidate-dashboard.tsx` | The left rule marks a row under INTEGRITY REVIEW, which is the one row state on this surface that must be findable while scanning a hundred candidates without reading any of them. The Candidate Dashboard Specification asks for it by name, and removing it would make a flagged row and a clean row identical at a glance on the exact surface where missing the distinction advances a candidate whose evidence is in question. It is not carrying the state alone: column 4 also reads "Under Review", the stage control shows a lock with a tooltip, and the state is announced to a screen reader with its meaning. |
| `side-tab` | `frontend/components/candidate-dashboard/candidate-dashboard.test.tsx` | The test asserts the rule above is present, so the class it is testing for has to appear in the assertion. Excepting the component without excepting its test would leave the gate failing on the thing that proves the gate's own exception is still true. |

## Findings that were FIXED rather than excepted

Recorded so a future reader can see what the bar is, and so nobody re-adds one
believing it had been accepted.

| Antipattern | Where | What was done |
|---|---|---|
| `ai-color-palette` | `about/page.tsx` (x2), `workflow-animation.tsx`, `workflow-frame.tsx`, `step-scenes.tsx` | Violet/indigo gradients replaced with single-hue navy or teal ramps. This was not a cosmetic swap: the whole indigo-violet brand ramp (`#5028E0`) was replaced with the sampled navy `#012654` and teal `#00888A`, because purple-to-blue is the single most recognisable tell of a generated interface and the detector was right about it. |
| `bounce-easing` | candidate assessment `page.tsx` | `animate-bounce` on the typing indicator replaced with an opacity fade. It appears while a candidate waits to be asked the next question about their career, and a bouncing dot there is the product being cheerful at somebody who is nervous. |
